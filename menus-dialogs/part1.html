מה בונים בחלק הזה, ולמה

כמעט בכל אפליקציה יש פעולות שלא צריכות כפתור קבוע על המסך: הגדרות, אודות, יציאה. המקום המקובל שלהן הוא Options Menu – התפריט שנפתח משלוש הנקודות שבראש המסך.

בחלק הזה נבנה תפריט עם שלושה פריטים. לחיצה על פריט תשנה את הטקסט שעל המסך:

צעד 1 מתוך 6

פרויקט חדש והפעלת ViewBinding

  1. פתחו פרויקט חדש: New Project → Empty Views Activity.
  2. שם הפרויקט: MenuDialogDemo. שפה: Java.
  3. פתחו את הקובץ build.gradle.kts (Module :app).
  4. בתוך הבלוק android { } הוסיפו את השורות המסומנות:
build.gradle.kts (Module :app)
android {
    // ... everything that is already here stays

    buildFeatures {
        viewBinding = true
    }
}
  1. לחצו על Sync Now שמופיע בראש החלון, וחכו שהסנכרון יסתיים.

למה זה חשוב? אחרי הסנכרון נוצרת אוטומטית מחלקה בשם ActivityMainBinding, ודרכה ניגשים לכל רכיב שיש לו id בקובץ activity_main.xml. במטלה הזו לא משתמשים ב־findViewById בכלל.

צעד 2 מתוך 6

מוסיפים Toolbar למסך

שלוש הנקודות של התפריט יושבות על הסרגל שבראש המסך. בפרויקט חדש אין סרגל כזה, לכן מוסיפים אותו בעצמנו – ומתחתיו טקסט שיראה איזה פריט נבחר.

החליפו את כל התוכן של activity_main.xml בקוד הבא:

res/layout/activity_main.xml
<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:id="@+id/main"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical">

    <com.google.android.material.appbar.MaterialToolbar
        android:id="@+id/toolbar"
        android:layout_width="match_parent"
        android:layout_height="?attr/actionBarSize" />

    <TextView
        android:id="@+id/tvStatus"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:layout_margin="24dp"
        android:gravity="center"
        android:text="עדיין לא נבחר פריט"
        android:textSize="20sp" />

</LinearLayout>

שימו לב לשני ה־id: toolbar ו־tvStatus. בדיוק בשמות האלה נשתמש בקוד דרך ה־binding.

צעד 3 מתוך 6

מחברים את המסך לקוד עם binding

עכשיו ה־Activity צריך לטעון את המסך דרך ה־binding, ולהגיד למערכת שה־Toolbar שלנו הוא הסרגל העליון.

החליפו את התוכן של MainActivity.java בקוד הבא. את שורת ה־package שבראש הקובץ שלכם אל תמחקו – היא נשארת כמו שהיא.

MainActivity.java
import android.os.Bundle;

import androidx.activity.EdgeToEdge;
import androidx.appcompat.app.AppCompatActivity;
import androidx.core.graphics.Insets;
import androidx.core.view.ViewCompat;
import androidx.core.view.WindowInsetsCompat;

import com.example.menudialogdemo.databinding.ActivityMainBinding;

public class MainActivity extends AppCompatActivity {

    private ActivityMainBinding binding;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        EdgeToEdge.enable(this);

        binding = ActivityMainBinding.inflate(getLayoutInflater());
        setContentView(binding.getRoot());

        ViewCompat.setOnApplyWindowInsetsListener(binding.getRoot(), (v, insets) -> {
            Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
            v.setPadding(systemBars.left, systemBars.top, systemBars.right, systemBars.bottom);
            return insets;
        });

        setSupportActionBar(binding.toolbar);
    }
}

מה עושות השורות המסומנות?

  • ActivityMainBinding.inflate(...) – בונה את המסך ויוצר את האובייקט binding.
  • setContentView(binding.getRoot()) – מציג את המסך. שימו לב: לא R.layout.activity_main.
  • setSupportActionBar(binding.toolbar) – הופך את ה־Toolbar שלנו לסרגל העליון. בלי השורה הזו התפריט לא יופיע.

אם שם ה־package שלכם שונה מ־com.example.menudialogdemo, שורת ה־import של ActivityMainBinding תסומן באדום. מחקו אותה, עמדו על ActivityMainBinding ולחצו Alt+Enter כדי לייבא מחדש.

צעד 4 מתוך 6

יוצרים את קובץ התפריט

הפריטים של התפריט נכתבים בקובץ XML נפרד, בתיקייה משלו.

  1. לחצו לחיצה ימנית על התיקייה res.
  2. בחרו New → Android Resource File.
  3. בשדה File name כתבו main_menu.
  4. בשדה Resource type בחרו Menu, ואשרו.
  5. החליפו את תוכן הקובץ שנוצר בקוד הבא:
res/menu/main_menu.xml
<?xml version="1.0" encoding="utf-8"?>
<menu xmlns:android="http://schemas.android.com/apk/res/android">

    <item
        android:id="@+id/action_settings"
        android:title="הגדרות" />

    <item
        android:id="@+id/action_about"
        android:title="אודות" />

    <item
        android:id="@+id/action_exit"
        android:title="יציאה" />

</menu>

כל item הוא שורה אחת בתפריט: title הוא מה שהמשתמש רואה, ו־id הוא השם שבעזרתו נזהה בקוד על מה לחצו.

צעד 5 מתוך 6

מציגים את התפריט: onCreateOptionsMenu

הקובץ קיים, אבל ה־Activity עדיין לא יודע עליו. הוסיפו את הפעולה הבאה בתוך המחלקה MainActivity, אחרי onCreate:

MainActivity.java
@Override
public boolean onCreateOptionsMenu(Menu menu) {
    getMenuInflater().inflate(R.menu.main_menu, menu);
    return true;
}

והוסיפו בראש הקובץ:

import
import android.view.Menu;
  • המערכת קוראת לפעולה הזו בעצמה, פעם אחת, כשהיא בונה את הסרגל העליון.
  • inflate לוקח את הקובץ main_menu.xml והופך אותו לתפריט אמיתי.
  • return true אומר למערכת: "יש תפריט, תציגי אותו".

הריצו עכשיו. שלוש הנקודות אמורות להופיע, והתפריט נפתח – אבל לחיצה על פריט עדיין לא עושה כלום. את זה נתקן בצעד הבא.

צעד 6 מתוך 6

מגיבים לבחירה: onOptionsItemSelected

בכל לחיצה על פריט המערכת קוראת לפעולה הזו ומעבירה לה את הפריט שנבחר. אנחנו בודקים איזה פריט זה לפי ה־id שלו, ומעדכנים את הטקסט דרך ה־binding.

MainActivity.java
@Override
public boolean onOptionsItemSelected(@NonNull MenuItem item) {
    int id = item.getItemId();

    if (id == R.id.action_settings) {
        binding.tvStatus.setText("בחרת: הגדרות");
        return true;
    } else if (id == R.id.action_about) {
        binding.tvStatus.setText("בחרת: אודות");
        return true;
    } else if (id == R.id.action_exit) {
        binding.tvStatus.setText("בחרת: יציאה");
        return true;
    }

    return super.onOptionsItemSelected(item);
}

והוסיפו בראש הקובץ:

import
import android.view.MenuItem;
import androidx.annotation.NonNull;

רגע, איפה ה־binding של התפריט? מחלקת binding נוצרת רק לקובצי layout. לקובץ תפריט אין מחלקה כזו, ולכן את הפריטים מזהים עם R.id. את רכיבי המסך עצמם (כמו tvStatus) ממשיכים לעדכן רק דרך binding.

נקודת בדיקה

מה אמור לקרות כשמריצים

  • בראש המסך יש סרגל עם שם האפליקציה, ובקצה שלו שלוש נקודות.
  • לחיצה על שלוש הנקודות פותחת תפריט עם שלושה פריטים: הגדרות, אודות, יציאה.
  • לחיצה על "אודות" סוגרת את התפריט, והטקסט שעל המסך מתחלף ל"בחרת: אודות".
  • אותו דבר קורה עם שני הפריטים האחרים, כל אחד עם הטקסט שלו.
סרטון הדגמה – אוסיף כאן בקרוב

הכול עובד? מצוין. אם משהו לא מסתדר – המסך הבא בדיוק בשביל זה.

טעויות נפוצות

משהו לא עובד? בדקו כאן

לחצו על התיאור שמתאים למה שקורה אצלכם.

אין שלוש נקודות, התפריט לא מופיע בכלל
  • ודאו שב־onCreate יש את השורה setSupportActionBar(binding.toolbar);
  • ודאו ש־onCreateOptionsMenu מחזירה true.
  • ודאו ששם הקובץ ב־inflate זהה לשם הקובץ שיצרתם: R.menu.main_menu.
ActivityMainBinding מסומן באדום
  • בדקו שהוספתם viewBinding = true בקובץ של ה־Module (ולא בקובץ של ה־Project).
  • לחצו Sync Now וחכו לסיום.
  • שם המחלקה נגזר משם קובץ ה־layout: activity_main.xml הופך ל־ActivityMainBinding.
binding.toolbar או binding.tvStatus מסומן באדום

ה־id ב־XML לא תואם לשם בקוד. בדקו שכתוב שם בדיוק @+id/toolbar ו־@+id/tvStatus.

ניסיתי switch וקיבלתי Constant expression required

ב־Android Studio של היום ערכי R.id אינם קבועים, ולכן אי אפשר לשים אותם ב־case. משתמשים ב־if / else if, כמו בצעד 6.

האפליקציה קורסת מיד בפתיחה, וב־Logcat כתוב This Activity already has an action bar

ה־theme של האפליקציה כבר מוסיף סרגל משלו. פתחו את res/values/themes.xml וודאו שה־parent מסתיים ב־NoActionBar. בדקו גם את הקובץ שבתיקייה values-night.

התפריט נפתח, אבל לחיצה על פריט לא משנה כלום
  • בדקו שה־id שבתנאי זהה ל־id שבקובץ התפריט.
  • בדקו שהפעולה נקראת בדיוק onOptionsItemSelected ושיש מעליה @Override.

עכשיו אתם

הוסיפו לתפריט פריט רביעי משלכם:

  1. הוסיפו item חדש לקובץ main_menu.xml, עם id ו־title שאתם בוחרים.
  2. הוסיפו לו תנאי ב־onOptionsItemSelected.
  3. כשבוחרים בפריט, הטקסט ב־tvStatus משתנה להודעה משלכם – דרך binding בלבד.

לפני שמגישים, ודאו ש:

  • בתפריט מופיעים ארבעה פריטים וכל אחד מהם מגיב ללחיצה.
  • אין בקוד אף findViewById.
  • האפליקציה רצה בלי קריסות.

אתגר למי שרוצה: הוסיפו לאחד הפריטים את התכונה app:showAsAction="ifRoom" (ואת השורה xmlns:app="http://schemas.android.com/apk/res-auto" בתגית menu), והריצו. מה השתנה במקום שבו הפריט מופיע?
